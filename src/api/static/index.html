GTFS Data Model

The General Transit Feed Specification (GTFS) defines public transit data as a set of linked CSV files. The TFI feed is ingested through a three-layer pipeline — Bronze (raw), Silver (cleaned), Gold (aggregated) — before being served via this dashboard.

Dataset Reference

agency.txt Operator

Defines the transit operators — bus companies, rail operators, ferry services — that run the routes in the feed. Each operator has a unique ID that routes reference.

PK agency_id
Fields agency_name, agency_url, agency_timezone
routes.txt Operator

Each row is a named route (e.g. "Route 8", "NX"). Carries a short display number, a long descriptive name, and a route_type code that classifies it as bus, rail, tram, ferry, etc.

PK route_id   FK agency_id
Fields route_short_name, route_long_name, route_type
route_type 0 Tram · 1 Metro · 2 Rail · 3 Bus · 4 Ferry
calendar.txt Schedule

Maps a service_id to the days of the week it operates and its active date range. A weekday service has monday–friday = 1, saturday–sunday = 0. Trips reference this to define when they run.

PK service_id
Fields monday–sunday (0/1 flags), start_date, end_date
trips.txt Schedule

One row per individual journey — the 09:00 Route 8 from Dublin is a trip. Joins route, calendar, and shape. direction_id (0/1) separates outbound from inbound journeys.

PK trip_id   FK route_id, service_id, shape_id
Fields trip_headsign, direction_id
stop_times.txt Schedule Largest file

The core timetable. One row for every stop a trip calls at, with arrival and departure times. This is the largest file in the feed — the TFI dataset has ~7 million rows — and drives the timetable view and headway calculations.

FK trip_id, stop_id
Fields stop_sequence, arrival_time, departure_time
Times can exceed 24:00 for overnight services (e.g. 25:30:00)
stops.txt Geography

Physical bus stops, stations, and platforms with their GPS coordinates. Used for geospatial queries and the stop activity aggregation. A stop_code is the short human-readable identifier shown on signs.

PK stop_id
Fields stop_name, stop_lat, stop_lon, stop_code
shapes.txt Geography

An ordered sequence of GPS points that trace the geographic path of a trip on a map. Not required for scheduling — used for map rendering. Each point has a sequence number and distance-travelled value.

PK shape_id + shape_pt_sequence
Fields shape_pt_lat, shape_pt_lon, shape_dist_traveled

Processing Pipeline

🥉 Bronze Raw ingestion

Downloads the live TFI GTFS ZIP, extracts each .txt file, and writes it to Parquet with an ingestion timestamp. No transformations — data is stored exactly as received.

Outputs: one Parquet per GTFS file

🥈 Silver Clean & validate

Applies validation rules to every file. Records that fail critical rules are quarantined. Passing records are type-cast, normalised (dates, times, coordinates) and written as clean Parquet.

Outputs: cleaned Parquet + quarantine file

🥇 Gold Aggregated analytics

Joins and aggregates the Silver tables into five analytics-ready outputs used by this dashboard and exportable for Power BI.

• route_summary — trips, stops, service days per route
• stop_activity — departures & peak hours per stop
• operator_summary — routes & trips per agency
• headway_analysis — avg/min/max gap between trips
• calendar_coverage — active days per service
